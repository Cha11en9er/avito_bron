## Почему лист «настройки» был пустой

Лист уже существовал в таблице с одной пустой строкой. Старый код при пустом `get_all_values()` падал с ошибкой до записи дефолтов. Сейчас:

- пустой лист **автоматически заполняется** при первом чтении;
- недостающие ключи **дописываются** без удаления ваших значений;
- можно принудительно: `python -m google_sheets seed-settings`.

Формат листа: **A = ключ**, **B = значение**, **C = описание**.

## Настройки (лист «настройки»)

**ID таблицы** задаётся только в файле `.env` (`AVITO_GOOGLE_SHEET_ID`), не на листе настроек.

Подробные пояснения в колонке **«описание»** на листе. Ниже — краткая шпаргалка. Пересоздать лист: `python -m google_sheets seed-settings --force`.

### Очередь и диапазон

| Ключ | Значение для обычной работы |
|------|-----------------------------|
| `sync_from_links_sheet` | **1** — список URL из листа «ссылки»; новые URL дописываются в конец рабочих листов |
| `detail_range_from` / `detail_range_to` | **0** и **0** — все; **1** и **10** — ссылки №1–№10 (как в таблице: строка = номер+1) |

### Что парсить

| Ключ | Значение |
|------|----------|
| `run_calendar` | **1** — бронь и цены (основное) |
| `run_detail` | **0** — детальная карточка не нужна каждый день |
| `detail_fill_mode` | **append** — догонять только пустые «название» (если включите `run_detail=1`) |
| `detail_only_empty_title` | **1** — вместе с append |
| `calendar_mode` | **daily** — не удалять старые строки; **primary** — один раз пересобрать листы брони/цен по «ссылки» (все старые данные стираются) |

### Итерации парсинга (3 слота в «логи ежедневного парсинга»)

Вместо привязки к календарным дням — **3 итерации** (три прогона). В строке 1 листа логов:

| Блок | Столбцы | Содержимое |
|------|---------|------------|
| 1 | C–F | ит.N, дата, время, статус (между блоками пустые B, G, L) |
| 2 | H–K | … |
| 3 | M–P | … |

| Ключ | Описание |
|------|----------|
| `parse_iteration` | Текущий номер итерации (можно менять вручную) |
| `iteration_progress` | **Строка листа**: `0` — с начала (строка 2); `2188` — со строки 2188. После полного прохода → `0` и `parse_iteration` +1 |
| `iteration_progress_for` | Служебное: для какой `parse_iteration` записан прогресс. При **ручной** смене номера итерации парсер обнуляет `iteration_progress` |
| `iteration_logs_cleared_for` | Служебное. При **старте новой** итерации парсер очищает её блок в логах (ит./дата/время/статус) и пишет заново |

При смене `parse_iteration` (вручную или после полного прохода) в **своём слоте** (кольцо из 3 блоков) старые даты/статусы **стираются**.

| `iteration_slot_0/1/2` | Какой номер итерации отображается в каждом блоке логов |

**Кольцо слотов:** итерация 4 → слоты `4, 2, 3`; итерация 5 → `4, 5, 3` (замена по формуле `(N-1) % 3`).

После **полного** прохода всех ссылок в одном запуске парсер **останавливается**: в настройках
`parse_iteration` +1, `iteration_progress` = 0. Второй прогон в том же процессе **не** стартует —
следующая итерация только при следующем ручном `python -m parser` (старт с начала, если в логах
для этой итерации ещё нет статусов).

Пересборка листа (новая шапка + список URL по тем же правилам, что и очередь парсера): `python -m google_sheets seed-logs`. Старые значения в ячейках логов при этом **стираются**. После смены схемы столбцов пересоберите лист, иначе дата/статус сместятся.

### Нумерация (таблица, консоль, настройки)

Везде **номер строки листа**: `iteration_progress=2188` → данные в **строку 2188** (строка 1 — заголовки, первая ссылка — строка 2). В консоли: `31.05.2026 21:58:51  2188/2203`, затем `брони`, `цены`, `запись`.

### Диапазон ссылок (`detail_range_from` + `detail_range_to`)

Работает **всегда** (не нужен `detail_fill_mode=range`).

| from | to | Результат |
|------|-----|-----------|
| `0` | `0` | **Все** ссылки |
| `2188` | `2188` | Только **строка 2188** |
| `2` | `11` | **Строки 2–11** включительно |
| `2188` | `0` | С **строки 2188** до конца |

### Детальный парсер

| Ключ | По умолчанию | Описание |
|------|--------------|----------|
| `run_detail` | `0` | **1** — парсить «детальная информация» |
| `detail_fill_mode` | `append` | `primary` — пересоздать лист и все URL; `append` — только пустое «название»; `rebuild` — очистить и заново |
| `detail_only_empty_title` | `1` | При `append`: **1** — пропускать строки с заполненным «название»; **0** — парсить все в диапазоне |

### Календарь (сдаваемость + цены)

| Ключ | По умолчанию | Описание |
|------|--------------|----------|
| `run_calendar` | `1` | **1** — парсить сдаваемость и цены |
| `calendar_mode` | `daily` | `daily` — дописать даты ≥ сегодня; `primary` — пересоздать листы (нужен `sync_from_links_sheet=1`) |
| `calendar_start_date` | `03.05` | Старт столбцов при `primary` |
| `calendar_start_year` | `2026` | Год для заголовков `ДД.ММ` |
| `calendar_horizon_days` | `90` | Только для `calendar_mode=primary` (сетка дат при пересоздании) |

**Сдаваемость / цены:** в ячейки пишутся дни от «сегодня» до последнего слота на сайте. Между свободными датами — `1`. Цены только для интервалов ровно в одну ночь (запись в день заезда).

Имена листов (`sheet_*`) — внизу листа «настройки», после пустых строк; менять только если переименовали вкладки в таблице.

## Изменили лист «ссылки»: удалили строки, добавили новые

При **`sync_from_links_sheet=1`** и запуске парсера:

| Действие | Поведение |
|----------|-----------|
| URL **убрали** из «ссылки» | Строка с этим URL **удаляется** (со смещением вверх) на «сдаваемость», «цены», «логи» и «деталь» (если лист используется) |
| URL **добавили** в «ссылки» | Строка **дописывается в конец** рабочих листов (`calendar_mode=daily`) |

Порядок строк на рабочих листах **не копируется** с «ссылки» один в один — важен столбец A (URL), не совпадение номеров строк.

| Задача | Что сделать |
|--------|-------------|
| Полностью **пересобрать** календари с нуля | `calendar_mode=**primary**` (один раз), затем снова `daily` |
| **Логи** — новая шапка итераций + список URL | `python -m google_sheets seed-logs` |
| **Деталь** — пересобрать по «ссылки» | `detail_fill_mode=primary` (один раз) |

## Основной парсер (`python -m parser`)

**Сдаваемость** — datepicker на карточке (**4 месяца**: две панели как открылись + два клика «вперёд»). В лист пишутся только даты **≥ сегодня (MSK)** на момент обработки ссылки; прошлые столбцы не перезаписываются (на сайте прошлые дни часто выглядят «занято»). Если прогон переходит полночь — для каждой новой ссылки берётся актуальный «сегодня».

**Цены** — карусель «ближайшие даты». Плюс детальная карточка и телефон (если `run_detail=1`).

Сценарий на карточке (**~20 с**): **5 с** ожидание → скролл к календарю → **5 с** в datepicker (4 мес.) → **3 с** пауза → **7 с** карусель цен. При `run_detail=0` деталь и телефон не собираются.

Занято/свободно: `datepicker-day-disabled` → `1`, `datepicker-day-available` → `0`.

**Запасной режим** (старая карусель брони): `python -m parser.all_info_carousel`.

**Тест calendar** (3 URL, консольный отчёт): `python -m parser.all_info_calendar`.

## Семантика данных

### Сдаваемость

- `0` — свободно (datepicker: `datepicker-day-available`)
- `1` — занято (`datepicker-day-disabled`)
- `нету на сайте` — объявление снято (только **4 дня** с даты парсинга, включая сегодня; более старые даты в строке не трогаются). Если объявление **снова появилось** — ячейки **до сегодня** с `нету на сайте` **сохраняются**; с **сегодня** пишутся `0` / `1` / цена / пусто по слотам Avito

### Цены

- Строка с ценой за ночь; при снятом объявлении — `нету на сайте`

### Историчность

В ячейки с датой **начиная с сегодня** (MSK) пишутся новые значения; **более ранние** даты не перезаписываются (в т.ч. остаётся исторический `нету на сайте`). Снято с сайта — маркер на **4 дня** с даты парсинга. Вернулось на сайт — с сегодня снова `0`/`1`/цена.

**Длинный прогон через полночь** (итерация 12+ часов, старт вечером 31.05): для каждой ссылки день записи = `max(день открытия ссылки, сегодня MSK на момент записи)`. Ссылка, начатая 31.05 в 23:59 и законченная 01.06 в 00:00, **не затирает 31.05** в листе (на сайте прошлые дни выглядят «занято»). После смены дня ссылки, уже обработанные **до** полуночи, в той же итерации **пропускаются** повторно.
