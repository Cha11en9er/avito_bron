## Почему лист «настройки» был пустой

Лист уже существовал в таблице с одной пустой строкой. Старый код при пустом `get_all_values()` падал с ошибкой до записи дефолтов. Сейчас:

- пустой лист **автоматически заполняется** при первом чтении;
- недостающие ключи **дописываются** без удаления ваших значений;
- можно принудительно: `python -m google_sheets seed-settings`.

Формат листа: **A = ключ**, **B = значение**, **C = описание**.

## Настройки (лист «настройки»)

### Общие

| Ключ | По умолчанию | Описание |
|------|--------------|----------|
| `sync_from_links_sheet` | `1` | **1** — очередь с «ссылки», дописать URL на рабочие листы. **0** — URL только из столбца A листа «сдаваемость по дням», **без** синхронизации с «ссылки» |
| `detail_range_from` | `0` | Индекс первой ссылки (с нуля) |
| `detail_range_to` | `0` | Индекс конца (**не включая**). См. таблицу диапазонов ниже |
| `browser_restart_every` | `10` | Перезапуск браузера после N объявлений |
| `spreadsheet_id` | (в коде) | ID таблицы |

### Итерации парсинга (3 слота в «логи ежедневного парсинга»)

Вместо привязки к календарным дням — **3 итерации** (три прогона). В строке 1 листа логов:

| Блок | Столбцы | Содержимое |
|------|---------|------------|
| 1 | C–F | ит.N, дата, время, статус (между блоками пустые B, G, L) |
| 2 | H–K | … |
| 3 | M–P | … |

| Ключ | Описание |
|------|----------|
| `parse_iteration` | Текущий номер итерации (можно менять вручную) |
| `iteration_progress` | Служебный счётчик (обновляется парсером). **Старт очереди** — по листу логов: первая ссылка без статуса в блоке текущей итерации; если логи стёрли — снова с начала диапазона |
| `iteration_slot_0/1/2` | Какой номер итерации отображается в каждом блоке логов |
| `iteration_status` | `running` / `complete` / `idle` |

**Кольцо слотов:** итерация 4 → слоты `4, 2, 3`; итерация 5 → `4, 5, 3` (замена по формуле `(N-1) % 3`).

После **полного** прохода всех ссылок `parse_iteration` увеличивается на 1, `iteration_progress` сбрасывается в 0.

Пересборка листа (новая шапка + список URL по тем же правилам, что и очередь парсера): `python -m google_sheets seed-logs`. Старые значения в ячейках логов при этом **стираются**. После смены схемы столбцов пересоберите лист, иначе дата/статус сместятся.

### Диапазон ссылок (`detail_range_from` + `detail_range_to`)

Работает **всегда** (не нужен `detail_fill_mode=range`).

| from | to | Результат |
|------|-----|-----------|
| `0` | `0` | **Все** ссылки в выбранном источнике |
| `0` | `1` | Только **первая** ссылка (индекс 0) |
| `0` | `10` | Первые **10** ссылок (индексы 0…9) |
| `5` | `15` | Индексы 5…14 (10 штук) |

Интервал: **`[from, to)`** — правая граница не входит.

### Детальный парсер

| Ключ | По умолчанию | Описание |
|------|--------------|----------|
| `run_detail` | `0` | **1** — парсить «детальная информация» |
| `detail_fill_mode` | `append` | `primary` — пересоздать лист и все URL; `append` — только пустое «название»; `rebuild` — очистить и заново |
| `detail_only_empty_title` | `1` | При `append`: **1** — пропускать строки с заполненным «название»; **0** — парсить все в диапазоне |

### Календарь (сдаваемость + цены)

| Ключ | По умолчанию | Описание |
|------|--------------|----------|
| `run_calendar` | `1` | **1** — парсить сдаваемость и цены |
| `calendar_mode` | `daily` | `daily` — дописать даты ≥ сегодня; `primary` — пересоздать листы (нужен `sync_from_links_sheet=1`) |
| `calendar_start_date` | `03.05` | Старт столбцов при `primary` |
| `calendar_start_year` | `2026` | Год для заголовков `ДД.ММ` |
| `calendar_horizon_days` | `90` | Только для `calendar_mode=primary` (сетка дат при пересоздании) |
| `debug_dump_html` | `0` | `1` — HTML страницы после прокруток и брони в `debug_html_dir` |
| `debug_html_dir` | `debug_html` | Папка дампов от корня проекта |

**Сдаваемость / цены:** в ячейки пишутся дни от «сегодня» до последнего слота на сайте. Между свободными датами — `1`. Цены только для интервалов ровно в одну ночь (запись в день заезда).

## Пример: тест сдаваемости и цен на 10 ссылок (без «ссылки»)

На листе **«настройки»** выставьте:

| ключ | значение |
|------|----------|
| `run_detail` | `0` |
| `run_calendar` | `1` |
| `sync_from_links_sheet` | `0` |
| `calendar_mode` | `daily` |
| `detail_range_from` | `0` |
| `detail_range_to` | `10` |

Затем:

```bash
python -m google_sheets seed-settings   # если лист пустой
python -m parser
```

Поведение:

1. URL берутся из столбца A листа **«сдаваемость по дням»** (первые 10 строк с ссылками).
2. Лист **«ссылки»** не читается и на него ничего не копируется.
3. После каждой карточки обновляются **сдаваемость**, **цены** и **логи**.

Одна ссылка для проверки: `detail_range_from=0`, `detail_range_to=1`.

Полный прогон по всем URL на листе сдаваемости: `detail_range_from=0`, `detail_range_to=0`.

## Семантика данных

### Сдаваемость

- `0` — ночь есть в карусели брони
- `1` — занято
- `нету на сайте` — объявление снято (все ячейки строки)

### Цены

- Строка с ценой за ночь; при снятом объявлении — `нету на сайте`

### Историчность

В ячейки с датой **≥ сегодня** (MSK) пишутся только новые значения; прошлые даты не перезаписываются (кроме случая «снято» — тогда вся строка).
